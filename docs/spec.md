# OPTCG Deck Buyer — สเปก v2 (อนุมัติ)

เครื่องมือบันทึกการซื้อการ์ด One Piece Card Game มาประกอบเด็ค: ลากการ์ดไปไว้กับคนขาย/ร้านแต่ละราย
เพื่อดูว่าซื้อกับใครกี่บาท ได้ใบไหนบ้าง และต้นทุนรวมของเด็ค

## ขอบเขต

- ไม่มีค่าใช้จ่ายอื่นนอกจากค่าการ์ดและค่าส่ง
- ไม่มีการบันทึกการขายและไม่คิดกำไร (อาจเพิ่มภายหลัง)
- เว็บหน้าเดียว ไม่มีเซิร์ฟเวอร์ ข้อมูลอยู่ในเบราว์เซอร์ ย้ายด้วย Export / Import JSON

## ข้อมูล

```js
{
  sellers: [{ id, name, shipping }],              // ค่าส่งต่อกล่อง (คนขาย/ร้าน)
  decks: [{
    id, name,
    items: [{ code, qty }],                       // การ์ดที่เด็คต้องมี
    purchases: [{ id, sellerId, code, qty, price }] // การ์ดที่จัดเข้ากล่องแล้ว
  }],
  currentDeckId,
  cards: { [code]: { name, rarity, image } }      // cache จาก optcgapi.com
}
```

- ค่าส่งคิดเมื่อกล่องนั้นมีการ์ดอย่างน้อย 1 ใบ
- ลบการ์ดออกจากเด็คได้เฉพาะเมื่อไม่มีการจัดซื้อของรหัสนั้นอยู่

## การคำนวณ (buy.js)

- `left(code)` = max(0, จำนวนในเด็ค − จำนวนที่จัดแล้ว) ต่อการ์ด
- `over(code)` = max(0, จัดแล้ว − จำนวนในเด็ค) ใช้เตือน
- ยอดกล่อง = Σ(qty × price) + ค่าส่ง (ถ้ามีการ์ด)
- ต้นทุนเด็ค = Σ ยอดทุกกล่อง; จำนวนที่ยังขาด = Σ left

## หน้าจอ

- แถบบน: เลือกเด็ค เพิ่มเด็ค ลบเด็ค และยอดรวมเด็ค (ค่าการ์ด ค่าส่ง ต้นทุนรวม ยังขากี่ใบ)
- ซ้าย: ลิสต์การ์ดในเด็ค แสดง "เหลือ N ใบ" เพิ่มการ์ดด้วยรหัสและจำนวน
- ขวา: กล่องคนขายแต่ละคน มีชื่อ ค่าส่ง ยอดกล่อง และรายการที่จัดแล้ว (ลบรายการได้) เพิ่มคนขายได้
- **ลาก** การ์ดจากลิสต์ไปวางในกล่อง หรือ **แตะการ์ดแล้วแตะกล่อง** (ใช้บนมือถือ)
- หลังวาง เปิดหน้าต่างให้กรอกจำนวน (ค่าเริ่มต้น = ที่เหลือ) และราคาต่อใบ (ค่าเริ่มต้น = ราคาล่าสุดของรหัสนั้น)

## กรณีผิดปกติ

- จำนวนหรือราคาไม่ถูกต้อง (ติดลบ ไม่ใช่ตัวเลข) ไม่บันทึก
- ดึงข้อมูลการ์ดไม่ได้ ให้พิมพ์ชื่อเองได้
- Import ไฟล์ผิดรูปแบบ แจ้งเตือนและไม่ทับข้อมูลเดิม

## ทดสอบ

- `npm test` ทดสอบ buy.js (left, over, ยอดกล่อง, ค่าส่ง, ยอดเด็ค)
- ทดสอบหน้าจอในเบราว์เซอร์ด้วยเด็คตัวอย่าง: เพิ่มการ์ด ลากไปกล่อง ตรวจยอด และ Export/Import

## UI v3 (อนุมัติ 2026-11-02): เน้นรูป เต็มจอ ลื่น

- จอคอมเป็นหลัก: แถบบนติดตลอด (เลือกเด็ค + ยอด 4 ช่องตัวใหญ่), ซ้าย ~60% ตารางการ์ด, ขวา ~40% กล่องคนขาย, เลื่อนแยกกัน
- การ์ดในเด็คแสดงรูปเต็มใบ ป้าย ×จำนวน, แถบ "เหลือ N"/"ครบ", ครบแล้วจาง; คลิก = ดูรูปใหญ่; ลากแล้วเห็นรูปการ์ด
- ลากไฟล์ .deck มาวางบนฝั่งซ้ายเพื่อนำเข้าได้
- กล่องคนขาย: หัวกล่องชื่อ/ราคารวม/ค่าส่ง/ยอดตัวใหญ่, ข้างในเป็นรูปการ์ดเล็ก ×จำนวน, ชี้แล้วมีปุ่มลบ, ลากผ่านกล่องเรืองแสง
- กล่องที่ตั้งราคารวมแล้ว: วางการ์ด = เพิ่มจำนวนที่เหลือทันที (รวมกับรายการรหัสเดิมในกล่อง) ไม่เด้งหน้าต่าง; ถ้าครบแล้วแจ้งเตือนและไม่เพิ่ม
- ธีมมืดเป็นค่าเริ่มต้น สลับธีมสว่างได้; แอนิเมชัน ~150ms ปิดเมื่อ prefers-reduced-motion
- จอแคบกว่า 860px: คอลัมน์เดียว แตะการ์ดแล้วแตะกล่อง

## บันทึกขึ้นเซิร์ฟเวอร์ (อนุมัติ 2026-11-19, แทนแบบ "ซิงก์" ที่ต้องเปิดเองและใส่รหัส)

ความต้องการ: ใช้คนเดียว · ไม่มีรหัส · ไม่มีเน็ตก็ใช้ได้ · ชนกัน → ชุดที่แก้ล่าสุดชนะ ชุดที่แพ้เก็บลงประวัติ

- `api/_core.js` (Turso ผ่าน HTTP `/v2/pipeline`), `api/sync.js` (GET/PUT), `api/history.js` (GET รายการ / GET ?id=)
- ตาราง `deck_state(id='main', data, edited_at, updated_at)` และ `deck_history(id, data, edited_at, saved_at, reason)`
- PUT `{ data, editedAt, baseUpdatedAt, restore? }`: base ตรง → บันทึก (สำรองชุดเดิมแบบเว้น 10 นาที);
  base ไม่ตรง → `editedAt` ใหม่กว่า/เท่ากัน ชนะ (ชุดเดิม → ประวัติ `overwritten`),
  เก่ากว่า → ตอบ `stale` พร้อมชุดล่าสุด (ชุดที่ส่งมา → ประวัติ `lost`); `restore` → สำรอง `before_restore` เสมอ
- เขียนด้วย `UPDATE ... WHERE updated_at = ?` แล้วลองใหม่ถ้าแทรกกัน; ประวัติเก็บ 50 ชุด
- `cloud.js`: เก็บในเบราว์เซอร์ก่อน ส่งตามหลัง 1.5 วินาที ดึงตอนเปิดแอป/กลับมาที่แท็บ/กลับมาออนไลน์;
  เครื่องว่าง → โหลดจากเซิร์ฟเวอร์; ได้ `stale` → ใช้ชุดล่าสุดแล้วแจ้งเตือน; กู้คืน = ใช้ในเครื่อง + PUT `restore`
- env: `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` · `currentDeckId` ไม่ส่งขึ้นเซิร์ฟเวอร์ · `file://` ซ่อนปุ่มประวัติ
- เทส: Turso จำลองด้วย SQLite จริง (`node:sqlite`) รัน SQL ชุดเดียวกับที่ส่งไป Turso
